# Agent guide

This repository is a curated research map. The three root READMEs are generated from data files.

- **Finding, adding or correcting works:** follow [docs/AUTO_UPDATE.md](docs/AUTO_UPDATE.md). Start at its §0. The queue of works still to read is the `pending` candidates in `data/triage.yaml`.
- **Entry fields and checks:** [docs/MAINTENANCE.md](docs/MAINTENANCE.md). Scope identities are defined in [CONTRIBUTING.md](CONTRIBUTING.md).
- **Do not edit the generated READMEs by hand:** `README.md`, `README.zh-CN.md` and `README.ja.md` come from `data/works.yaml` and `data/site.yaml`. Edit those files, then run `python3 scripts/build_readme.py`.
- **Robotics branch: two repositories, one source.** `robotics/` and `assets/robotics/` are generated by the same command for [awesome-multimodal-agentic-coding-robotics](https://github.com/jiangjin1999/awesome-multimodal-agentic-coding-robotics). Two rules always hold:
  1. **Stage 3 and 2.6 are identical in both repositories.** Entries, order, numbering and summaries all come from `data/works.yaml`. Never edit `robotics/`, the generated figures or the robotics repository's files by hand.
  2. **Every paper update updates both.** Commit the regenerated `robotics/` and `assets/robotics/` together with the data change; `--check` fails if they are stale. Once the commit is on `main`, the robotics repository copies it within an hour. To publish at once, run its "Sync from upstream" workflow.

  The robotics README's opening (taxonomy figure, overview, taxonomy table) comes from the `robotics` block in `data/site.yaml`. See [docs/MAINTENANCE.md](docs/MAINTENANCE.md#robotics-branch-repository).
- **Before committing, run:**

  ```sh
  python3 scripts/build_readme.py --check
  python3 -m unittest discover -s scripts -p 'test_*.py'
  ```
